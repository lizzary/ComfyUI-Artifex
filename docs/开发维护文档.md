# ComfyUI-Artifex 开发维护文档

## 项目定位

本仓库是 ComfyUI custom node 插件，负责图像编码、暂存、队列、Artifex 子进程生命周期及 ComfyUI 前端入口。Artifex 的数据库、图像持久化、缩略图、颜色组事务等继续由原版后端负责。

随仓库附带的是 [Artifex v2.6.1](https://github.com/lizzary/Artifex/releases/tag/v2.6.1) 的官方三平台二进制和原版 React 静态前端。**没有修改独立部署版源码，也没有新增 Artifex API。** 原版没有分组 URL，用户已明确选择所有图库入口打开主页；“打开当前分组 ↗”保留按钮名称，不实现深链或 DOM 模拟点击。

节点类名 `SaveInArtifex` 和输入字段是已保存工作流的兼容接口。改动时保持旧工作流仍能载入。

## 运行约束

`bin/` 视为发行资源。启动时只把当前平台可执行文件和动态库复制到 `runtime/bin/`，再运行副本。Artifex 的 `config.toml` 固定相对可执行文件定位，因此配置必须位于 `runtime/bin/config.toml`；不能只修改工作目录来隔离配置。

首次写入配置时设置插件 `data/` 为数据库目录、关闭自动打标、上传策略为 `save_all`。已有配置不覆盖，用户可以通过 Artifex 自身设置修改数据库目录。前端通过 `--frontend` 指向 `bin/frontend/`。

启动参数含 `--no-ui --host 127.0.0.1 --port <空闲端口>`；Windows 使用 `CREATE_NO_WINDOW`。只管理自己创建的子进程，不能探测到别的 Artifex 后就接管或终止它。操作前检查 PID 仍存活，再请求现有 `/api/groups` 和 `/api/settings`；无需增加 health API。

启动尝试总计 3 次；第 2、3 次前分别等待 1 秒、2 秒。单次等待 HTTP 就绪默认最多 120 秒，为启用打标后的本地大模型加载留出时间。启动锁防止并发节点同时拉起多个后端。ComfyUI 退出时清理自己持有的子进程。

Artifex 加载模型期间会持有图库锁，正常运行中的 API 探活可能超时。仅在已经取得图库 token、同一个受管子进程仍存活、且不处于首次启动或重启就绪阶段时，API **超时**才允许补充请求静态主页 `GET /`；主页返回 200 且进程仍未改变时视为存活，避免误杀正在加载模型的后端。HTTP 错误（包括 409）不走此回退。首次启动和受管重启仍必须通过 `/api/groups` 与 `/api/settings` 校验才算就绪。静态探活必须使用 GET，原版主页的 HEAD 请求返回 405。

`X-Artifex-Library` 是后端图库身份。相同数据库路径的受管进程重启可以映射旧身份；用户切换数据库时不映射旧身份，防止旧预览误删新数据库里同 ID 的图片。不要移除此检查。

每个保存批次用 `client.library_session()` 固定线程内的图库身份，覆盖名称解析和上传全过程；即使切库发生在两次解析请求之间，也不能把旧分组 ID 用到新图库。

## 保存流程与失败语义

1. 将 IMAGE batch 转成 PNG 字节。除非 ComfyUI 禁用了元数据，否则写入 `prompt` 和 `extra_pnginfo`；整个批次先完成内存编码。
2. 以 UTC 时间戳和进程序号命名临时目录与文件，创建 `staging/you_are_free_to_delete_all_file_here`，先尝试把本次所有 PNG 写入暂存目录，再发出任何 Artifex 请求。
3. 写盘失败记录 `logs/plugin.log`，仍使用内存队列上传；部分写入的残留允许用户删除，但不再执行该批次的完成目录删除。
4. 解析目标分组和颜色组；逐文件上传。Artifex 上传响应是事务完成后的结果，成功结果可立即使用图像 ID。节点启用自动打标时，再对刚保存的图片调用现有 retag 接口。
5. 如有颜色组，再通过颜色操作端点写人工分组。文件成功持久化并完成关联，或后端明确跳过后，才从队列出队。无法识别的格式和后端明确的尺寸限制属于可跳过错误；网络/数据库等错误必须报错，不能悄悄出队。
6. 生成 ComfyUI `temp/artifex/` 预览。队列清空后仅调用一次暂存目录删除；删除失败只记日志，不影响节点成功。

队列不写入数据库或 JSON，不跨 ComfyUI 重启恢复。上传请求超时可能已经提交成功，因此不要盲目重试 POST。发生上传、颜色关联等异常时，本次节点失败并保留已暂存的文件，供人工恢复；用户重跑可能产生新图，符合 `save_all`。

预览缓存与暂存分开，因此批次清理不影响原生图像预览。删除使用仅本进程持有的随机 token，绑定图像 ID、图库身份和缓存路径；接口不接受任意文件路径。重启后的旧 token 已失效，可到 Artifex 主页管理图片。

## 分组与颜色组解析

优先级固定为 **STRING 名称输入 → 节点下拉选项 → 默认值**。分组默认名 `ComfyUI`，颜色组默认显示“无 / None”，不写人工分配。每个 STRING 插口与对应下拉菜单放在同一行；输入连接时，仅禁用对应控件，保留原选项作为回退值。

普通分组下拉内部值为 `id:<整数>`，不是显示名称。全部重名项均追加 `(id:...)`。名称输入先 trim，普通分组最大 100 个 UTF-8 字节；已存在同名组时选择 `illustration_count` 最大者，同数量选最小 ID；没有则创建。

颜色组来自 `/api/group-config` 中该分组的所有配置集，内部值为 `set_id:pair_id`。自定义名称优先，没有自定义名称时由规则文本显示名称。名称重复时，按各配置集内实际生效的图片数选择：人工分配优先，其次按匹配优先级计算规则，最后是未分组。

规则计数实现须与上游 `frontend/src/utils/grouping.js` 保持一致，包括精确 tag、提示词子串、AND 优先于 OR、NOT 和括号。更新上游时重点核对这里。当前会分页读取分组图片来计算重名颜色组的数量；超过 100000 张的计数边界会报错并走选项回退，不做不可靠推断。

缺失颜色组创建到当前活动配置集；若没有活动配置集，则先创建名为 `ComfyUI` 的配置集。通过 `color-operations` 提交 `create_set`、`create_pair`、`assign`，不要用“读整个配置→整体覆盖”的方式破坏并发写入。

“无 / None”意味着不写 `manual_assignments`；Artifex 中已存在的自动颜色规则仍然可能将图片分类。现有 API 没有对单次上传排除所有自动规则的标记。

自动打标开关可以操作，默认关闭。能力函数 `auto_tag_available()` 目前保留为待实现逻辑，默认放行，不把“尚未实现校验”解释为“不具备打标能力”。将来实现能力校验后，只有明确判断不可用时才禁用控件并显示“暂不可用”。

上传始终使用 `skip_auto_tag=true`，以免全局设置影响节点关闭打标的语义。节点启用打标时，客户端先 `GET /api/settings`，若 `auto_tag` 为 false，则通过 `PUT /api/settings` 写入 `auto_tag:true`，让 Artifex 加载已配置模型；随后仅对该节点刚保存的图像 ID 调用 `POST /api/illustrations/retag`。

这个设置修改会保留，不在节点结束后还原，以免并发任务仍在打标时模型被卸载；它也会影响 Artifex 图库手动上传的默认打标行为。节点开关关闭时始终跳过打标，即使 Artifex 全局设置已打开。首次生成 `runtime/bin/config.toml` 的 `auto_tag` 仍为 false。没有模型或打标失败时明确报错，不能当成上传跳过；已持久化的图片和暂存文件保留供用户判断是否重跑。整个流程只使用既有 HTTP API，不修改上游源码，也不下载模型。

## HTTP 合约

插件增加的路由属于 **ComfyUI 服务器**：

| 方法 / 路径 | 请求与响应 |
| --- | --- |
| `GET /artifex/options` | query: `group=default`、可选 `group_name`；返回 `groups`、`color_groups`、`auto_tag_available` |
| `POST /artifex/open` | JSON `target=gallery/group/staging`；服务端打开系统默认浏览器或暂存目录，成功返回 `opened` |
| `DELETE /artifex/images/{token}` | 删除本插件已生成的对应图像和预览；未知 token 返回 404 |

前端用 `api.fetchApi`，保留 ComfyUI 自己的基础路径和请求行为。图库入口只发送打开请求，由 ComfyUI 服务端确认 Artifex 就绪后调用系统默认浏览器打开其主页。打开操作只接受 loopback 客户端，URL 和目录由服务器固定计算。暂存目录不依赖后端存活，以便故障时恢复暂存文件。

所用 Artifex 端点：

| 方法 / 路径 | 用途 |
| --- | --- |
| `GET /api/groups`、`POST /api/groups` | 分组列表、创建、HTTP 探活 |
| `GET /api/settings`、`PUT /api/settings` | 获取数据库路径与打标设置；节点启用打标时按需启用后端打标以加载模型 |
| `GET /api/group-config` | 颜色配置集、规则、人工分配 |
| `GET /api/groups/{id}/illustrations` | 分页读图，计算重名颜色组数量 |
| `POST /api/groups/{id}/illustrations/upload` | multipart 字段 `files`、`skip_auto_tag`、`conflict_policy` |
| `POST /api/illustrations/retag` | 节点显式开启打标时，仅处理本次新增图像 ID |
| `POST /api/groups/{id}/color-operations` | 原子颜色配置操作 |
| `DELETE /api/illustrations/{id}` | 图像删除 |
| `GET /api/illustrations/{id}/file` | 真实后端冒烟测试核对原图 |

## 前端维护

通过 `app.registerExtension` 注册 commands、menuCommands、actionBarButtons。节点只追加必要的控件和删除菜单；预览继续由 ComfyUI 原生 IMAGE UI 实现。不要把图像画成固定大小的自定义 canvas，否则会丢失原生缩放和批次预览能力。

可见语言取自 `Comfy.Locale`，监听其变化后更新已有节点。动态下拉选项保留稳定 ID；刷新请求使用序号丢弃过期响应，避免快速切换分组后旧颜色组覆盖新结果。节点上的按钮 DOM widget 不进入序列化。旧工作流的 widgets_values 顺序为 `[group, color_group, auto_tag]`。

`auto_tag` 的布尔输入定义使用 `socketless=True`，只显示开关，不创建悬浮插口，也不允许转换为输入。当前 ComfyUI 前端的 BOOLEAN 控件仍可能生成插口，因此扩展还将该 widget 的 `options.socketless` 设为 true，并在创建节点、恢复旧工作流时通过原生 `removeInput` 清理仅 `auto_tag` 的插口。分组名和颜色组名仍是独立的 STRING 插口，通过原生 `slot.pos` 与 `arrange()` 对齐对应下拉行，同时更新连线端点和命中区域；不要把 STRING 插口绑定到 COMBO widget，否则 Primitive 节点会覆盖下拉回退值。

ComfyUI 1.57 前端实测注意事项：空 combo 值可能以 `null` 传给 `getOptionLabel`；DOM widget 的高度包含 20px 布局留白；菜单翻译来自 `main.json.menuLabels`，通过稳定的 `menubarLabel` 查找，不能只给 `command.label` 提供函数。`commands.json` 用于命令界面。服务端 `/i18n` 缓存需要重启才能加载新翻译文件。删除预览时替换 `app.nodeOutputs` 的整项对象，让原生和 Vue 预览存储均收到更新。

## 验证

在插件根目录使用 Python 3.11+ 和 Node.js 22：

```sh
python -m pip install numpy Pillow aiohttp
python scripts/verify_bundle.py
python -m unittest discover -s tests -v
node --test tests/frontend.test.mjs
python -c "import runpy; runpy.run_path('tests/smoke_backend.py', run_name='__main__')"
```

真实后端测试创建 `.artifex-integration-*` 临时图库，测试分组、颜色组、上传、原图读取、杀死后重启、删除和切换数据库后的旧身份拒绝。测试不访问插件正式 `data/`。Python 节点测试替换 ComfyUI 环境依赖，故仍需要在真实 ComfyUI 中导入 `examples/save-in-artifex.json` 验证端口、界面和工作流执行。

对已经加载本插件的独立 ComfyUI 测试实例，可运行 `python tests/smoke_comfy.py http://127.0.0.1:8199`：通过真实 `/prompt` 执行三张 EmptyImage，验证元数据、颜色关联、原生预览、删除、主页入口和暂存清理。脚本只删除自己创建的唯一测试分组。不要向正在执行用户工作流的实例运行故障注入测试。

UI 检查重点：中文/英文切换、重复名称显示、颜色默认显示“无 / None”、STRING 插口与下拉同排且接入后下拉变灰、自动打标默认关闭且可操作、两按钮同排、拖动预览尺寸、从预览删除单张、三处图库入口通过系统默认浏览器打开。当前维护环境是 Windows；Linux 和 macOS 二进制来自官方发行包，本机无法证明它们在对应操作系统上的运行结果。CI 在 Windows/Linux 执行真实后端冒烟测试。

## 更新二进制与发布

`scripts/vendor_artifex.py` 按 `bin/upstream.json` 的固定版本和 SHA-256 下载、校验和提取；它不会运行下载的程序或下载模型。运行：

```sh
python scripts/vendor_artifex.py --download
python scripts/verify_bundle.py
```

也可把下载好的原始压缩包放在 `.cache/artifex-release/`，不加 `--download` 离线打包。更新上游版本前，先核对 HTTP 合约和规则语义；改版本、URL、校验后再打包。React 前端取自同版本官方 Windows 压缩包，三平台共用。动态库仅保留规范名 `onnxruntime.dll` / `libonnxruntime.so` / `libonnxruntime.dylib`，上游的版本号别名不重复存储。不要使用 Git LFS 指针替代实际二进制，否则普通 `git clone` 不再保证即用。

Artifex 许可证来自官方包；ONNX Runtime 的 LICENSE 和 ThirdPartyNotices 必须与所带版本同步，保留 React 构建的 LICENSE.txt。变更随包文件后重新运行 vendor 脚本更新 `SHA256SUMS.json`，再检查 diff；校验清单应由已验证来源生成，而不是为了消除错误随意改哈希。

`.gitattributes` 将 `bin/**` 标为不转换换行，保证 Windows/Linux Git checkout 后官方文件仍保持相同 SHA-256。

Comfy Registry 元数据位于 `pyproject.toml`：固定包名 `comfyui-artifex`、PublisherId `lizzary`（无 `@`）、语义版本。发布工作流遵循 [官方文档](https://docs.comfy.org/registry/publishing)，读取 GitHub Secret `REGISTRY_ACCESS_TOKEN`，推送 `main` 的版本文件变更或手动触发。密钥不写进仓库、日志、例子或文档。

`.comfyignore` 排除开发文件与测试运行目录；`bin/`、`web/`、`locales/`、`examples/` 显式包含在发布包中。Git 默认仅打包已跟踪文件，因此首次发布前必须确认真实二进制和 SHA 清单已提交。只有完成全部检查后才推送版本/触发发行；准备发布配置本身不等于已发布。
